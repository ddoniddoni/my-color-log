# 자정과 오늘의 색 공개

관련 요구사항: FR-MISSION-001, FR-MISSION-002/003/004. 개인·친구방별 기존 시간대 정책과 서버가 결정한 미션을 유지한다. 공개 연출은 DB·RLS를 바꾸지 않으며, 아래 팔레트 교체만 별도 데이터 migration으로 적용한다.

## 일상 색상 팔레트 — 2026-10-26

`20261025185955_everyday_cl_mission_colors.sql`이 현재 팔레트다. 기본 8색은 각각 가중치 4, 특별 2색은 각각 1로 선택한다. 전체 34 중 기본색은 32(약 94%), 특별색은 2(약 6%)다. 날짜 기반 서버 결정이므로 실제 짧은 기간의 빈도를 보장하거나 연속 중복을 막는 정책은 아니다.

기존 행을 수정해 이름을 바꾸지 않고 `everyday-*` 새 ID 10개를 추가한다. 기존 오늘·과거 미션의 이름·HEX·ID와 기록은 그대로이며, **반영 후 처음 생성되는 날짜**부터 새 목록을 사용한다. 미생성 과거 날짜도 이 규칙을 따른다. 이미 결정된 과거 색은 비활성화되어도 조회할 수 있다. 흰색·검정·회색은 이번 후보에 포함하지 않는다.

서버 RPC는 인증·시간대·미래 날짜 제한을 유지한다. 날짜의 MD5 일부를 가중치 누적 구간에 대응하며, 날짜 포맷과 정렬을 명시해 세션 설정에 영향을 받지 않는다. 같은 날짜의 동시 요청은 한 미션으로 수렴한다. 공개 링의 10칸은 결과 공개 연출이며 선택 확률을 나타내지 않는다. 과거 색은 실제 목표색 + 현재 후보 9색으로 공개한다.

갈색·베이지 사진 강조는 [색 인식 검증 기록](color-isolation-evaluation.md)을 따른다. 새 10색의 대표색/대비 텍스트는 모두 sRGB 상대 휘도 대비 4.5:1 이상이다. 빨강의 대비 텍스트는 검정으로 지정했다. 앱 화면 전체의 접근성 검증을 대신하는 수치는 아니다.

검증: 최소 `cl_` 설치·이전 팔레트 포함 설치·전체 이력 설치에서 기존 행/미션과 다른 객체 보존, SQL 계약 11개씩 통과. 최종 migration 재적용에서 팔레트 계약, 8개 동시 요청, DateStyle 독립성, 가중치 범위, 후보가 없어도 기존 미션 조회를 확인했다. 공유 서버 적용 상태는 [운영 안내](shared-supabase.md#팔레트-업데이트)를 따른다. 네이티브 빌드·실기기 QA는 실행하지 않았다.

## 이전 팔레트 개선 기록 — 2026-10-22

아래는 당시 구현·검증 기록이다. 현재 설치에는 위 일상 색상 migration을 적용하며, 미적용인 이전 팔레트 migration을 별도로 재실행하지 않는다.

`20261021180718_refresh_cl_mission_palette.sql`은 **활성 10색을 유지**하면서 코랄 핑크·라임 그린을 비활성화하고 다음 두 색을 새 ID로 추가한다. 유지하는 8색의 모든 값과 비활성 색의 이름·HEX·ID는 보존한다.

| 색 | 대표색 | Tint | Shade | 대비 텍스트 | 관찰 문구 |
| --- | --- | --- | --- | --- | --- |
| 로열 퍼플 / Royal Purple | `#7B2FD0` | `#F0E5FC` | `#49177F` | `#FFFFFF` | 꽃잎이나 작은 소품에 숨어 있는 선명한 보라를 찾아보세요. |
| 딥 와인 / Deep Wine | `#8B1E4B` | `#F6E3EB` | `#56102C` | `#FFFFFF` | 붉은 잎이나 천에 스며든 깊은 와인빛을 찾아보세요. |

기존 미션은 다시 정하지 않는다. migration 이후 **처음 생성되는 날짜의 미션**부터 새 활성 목록을 사용한다. 이미 오늘의 색이 생성됐다면 그 결과도 유지한다. 미생성 과거 날짜를 나중에 조회하는 경우 역시 새 목록에서 최초 생성된다.

현재 `cl_get_daily_mission`과 `cl_get_mission_reveal_palette`는 변경하지 않는다. 서버는 실제 목표색을 먼저 포함한 뒤 다른 활성색 9개를 채우므로, 과거 코랄·라임 미션도 유효한 10칸 공개를 유지한다. 클라이언트는 받은 배열과 같은 순서에서 목표 ID를 찾아 회전하므로 클라이언트 랜덤·별도 색 재정렬·재추첨이 없다.

어두운 배경에서 새 와인색의 경계를 드러내기 위해 결과 디스크에 `borderStrong` 중립 테두리를 추가했다. 색 이름은 디스크 바깥에 계속 표시하며, 약 2.1초 연출·결과 유지·모션 감소 동작은 그대로다.

### 색 구분과 표시 검토

밝은/어두운 디자인 토큰 위의 링·디스크·칩·달력 셀을 비교했다. 이는 색 조합을 확인하는 별도 시각 검토이며 실제 기기 캡처는 아니다. 실제 공개 컴포넌트 테스트에서도 새 두 색의 이름·대표색·테마별 경계와 모션 감소를 확인했다.

[Oklab 원문](https://bottosson.github.io/posts/oklab/)의 linear sRGB 변환식으로 10색의 모든 45쌍을 비교했다. 최소 유클리드 거리는 기존 코랄/로즈의 `0.0614`에서 교체 후 로즈/토마토의 `0.0850`으로 늘었다. 새 보라와 기존 색 사이의 가장 가까운 쌍은 클리어 블루(`0.1744`)다. 이 수치는 색상 후보 간 비교용이며 사진의 색 인식 임계값이나 모든 사용자에 대한 식별 보장이 아니다. 새 대표색/흰 글자의 sRGB 상대 휘도 대비는 보라 `6.65:1`, 와인 `8.80:1`이다. 기존 색상 행의 대비 텍스트 값은 변경하지 않았다.

2026-10-22~2027-10-21의 **예시 365일**에 기존 서버 해시 공식을 적용하면 보라 29일, 와인 37일이고 전체 색상별 28~46일 범위다. 미래 미션을 서버에 미리 만들지 않았으며 실제 이미 결정된 날짜는 이 예시와 다를 수 있다. 연속 중복 방지 정책은 추가하지 않았다.

### 적용 상태

로컬 PostgreSQL에서 신규/기존 설치, 기록 보존, 권한 계약과 동시 요청을 검증했다. **공유 서버에는 아직 적용하지 않았다.** D/E의 새 색 인식 품질 확인 후 [공유 Supabase 안내](shared-supabase.md)의 단일 migration 적용 절차로 반영한다. 앱 빌드와 기기 설치·실행은 사용자 지시에 따라 전체 수정 후 마지막에 수행한다.

## 화면과 동작

- 공개 전 `00:00`을 중심으로 실제 서버 팔레트의 얇은 컬러 링을 보여준다. 결과 색 이름은 공개 전 접근성 레이블에도 노출하지 않는다.
- 링이 1,650ms 동안 감속한 뒤 중앙에 색과 관찰 문구가 420ms 동안 나타난다. 결과는 자동으로 사라지지 않으며 사용자가 다음 화면으로 넘어간다.
- 모션 감소 시 회전·확대를 생략하고 180ms 페이드만 사용한다. 한국어·영어, 밝은·어두운 테마와 세로 스크롤을 지원한다.
- 공개 순간 `expo-haptics`로 iOS Soft / Android Confirm 피드백을 1회 제공한다. 모션 감소·백그라운드·웹에서는 생략한다. 모듈이 없거나 기기 설정으로 사용할 수 없어도 공개와 저장은 계속 동작한다.
- 날짜와 카운트다운을 하나의 시계에서 갱신한다. 백그라운드에서는 타이머를 멈추고 복귀 즉시 갱신한다. 자정 이후 새날 안내와 새 미션 공개 화면으로 전환한다.
- 날짜·계정·미션이 바뀌면 이전 연출을 취소한다. 늦게 끝난 로컬 저장은 시작 당시 계정과 날짜에만 적용한다.
- 결과를 보여줄 때 로컬 공개 이력을 저장한다. 저장 실패 시 같은 색을 유지하고 다시 저장할 수 있다. 저장된 당일 결과는 재실행 시 공개 연출을 건너뛴다.

## 로컬 이력과 의존성

공개 이력을 `@mycolorlog/mission-reveal/v2/{userId}/{dateKey}`로 분리했다. 계정 구분이 없던 v1 이력은 새 계정에 승계하지 않으므로 업데이트 직후 당일 연출이 한 번 다시 나타날 수 있다. 기록·사진에는 영향이 없다. 계정 삭제 시 v1·v2 공개 이력을 모두 정리한다.

`npx expo install expo-haptics`로 SDK 57 호환 버전 `~57.0.3`만 추가했다. lockfile에는 해당 패키지 한 개만 추가되었다. 기존 development build에서 햅틱을 사용하려면 네이티브 빌드를 다시 만들어야 한다. 별도 환경 변수나 서버 설정은 없다. [Expo Haptics 공식 문서](https://docs.expo.dev/versions/v57.0.0/sdk/haptics/).

## 검증

```bash
npm test -- --runInBand MissionReveal missionReveal dailyColorClock dailyMission
npm run typecheck
npm run lint
npm test -- --runInBand
npx expo install --check
CI=1 npx expo export --platform ios --platform android --output-dir /tmp/mycolorlog-midnight-reveal-export
```

테스트는 자정·DST·앱 복귀, 공개 중복 실행, 결과 유지, 저장 재시도, 계정·날짜 변경 중 늦은 완료, 오프라인 공개 이력, 모션 감소를 확인한다. 브라우저 검증은 실제 컴포넌트를 임시 테스트 데이터로 렌더링하며 제품에 미리보기 경로나 테스트 데이터를 추가하지 않는다.

출시 전 실제 iOS/Android development build에서 햅틱 강도, 23:59:59 → 00:00, 공개 중 앱 종료·복귀, VoiceOver/TalkBack, 큰 글자와 작은 화면을 확인한다. 번들 생성과 브라우저 검증은 네이티브 빌드·실기기 검증을 대신하지 않는다.
