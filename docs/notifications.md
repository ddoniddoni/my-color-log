# 기록 알림

요구사항: FR-NOTIFY-001. 내 정보의 알림 설정에서 아침·저녁 시간과 종류를 선택한다. 저장을 확정한 사진이 한 장이라도 있으면 오늘 저녁 알림을 취소한다. 업로드가 끝나지 않았거나 실패한 사진도 기록으로 인정한다. 촬영 미리보기의 미확정 사진과 취소한 사진은 제외한다.

## 동작과 범위

- 개인 시간대의 날짜와 선택한 시각을 UTC 예약 시각으로 변환한다. DST에서 두 번 오는 시각은 첫 번째를 사용하고, 건너뛴 시각은 전환 간격만큼 뒤로 이동한다.
- 최대 30일치, 아침·저녁 합계 60건의 단발성 알림을 예약한다. 앱 시작, 포그라운드 복귀, 자정, 언어·시간대·설정·사진 변경 때 갱신한다. 변경 없는 예약은 유지한다.
- 서버의 사진 메타데이터와 기기의 촬영 큐를 함께 확인한다. 이미지 접근 URL을 얻지 못해도 서버의 사진이 있으면 기록으로 인정한다. 조회 결과가 불명확하면 오늘 저녁 알림을 보류한다.
- 마지막 사진 삭제 후 선택한 시간이 아직 지나지 않았으면 오늘 저녁 알림을 다시 예약한다. 지난 시각의 알림은 즉시 몰아서 보내지 않는다.
- 한국어·영어 제목과 본문을 사용한다. 언어 변경 시 기존 예약도 새 언어로 교체한다.
- 예약 수정 작업을 순서대로 처리하며, 계정·기록 상태가 바뀌면 이전 작업을 중단하고 최신 상태로 정리한다. 일부 예약 실패 시 저장한 설정을 다음 실행에서 다시 적용한다.
- 로그아웃 시 개인 예약을 취소한다. 설정은 기존과 동일하게 기기 단위로 유지하며, 계정 삭제 시 설정도 제거한다. 친구방 푸시 예약이나 다른 종류의 알림을 일괄 삭제하지 않는다.
- 알림을 누르면 로그인된 사용자의 오늘 화면으로 이동한다. 기존 친구방 알림의 방/기록 화면 이동은 유지한다. 비밀번호 복구 화면에서는 자동 이동을 보류한다.
- DB, RLS, 의존성, 푸시 자격 증명에 변경이 없다. 알림 데이터에는 경로 구분, 날짜, 예약을 만든 사용자 ID 등 최소 메타데이터만 포함하며 이메일·사진 URL·캡션·인증 토큰은 넣지 않는다.

## 로컬 알림의 제한

30일 동안 앱을 열지 않으면 기존 예약 기간 뒤의 알림은 재개하지 않는다. 앱을 다시 열면 앞으로 30일을 예약한다. 또한 앱이 꺼진 동안 다른 기기에서 기록하거나 시간대가 바뀐 사실은 다음 실행·동기화 때 반영된다. 앱이 실행되지 않아도 서버 기준으로 실시간 판정하는 기능은 별도의 서버 알림 설계가 필요하다.

알림 설정 화면의 문구에도 30일 갱신 방식을 안내한다. OS의 알림 권한, 방해 금지·절전·정확한 알람 설정에 따라 실제 표시 시각은 달라질 수 있다.

## 검증

```bash
npm test -- --runInBand dailyReminder zonedDateTime localNotificationRepository notificationNavigation
npm run typecheck
npm run lint
npm test -- --runInBand
```

단위·통합 테스트는 날짜·DST, 기록 판정, 예약 취소/복원, 권한, 언어 갱신, 부분 실패 복구, 로그아웃 경합, 앱 종료/실행 상태의 알림 이동을 검증한다. 네이티브 API는 테스트 대역을 사용하므로 실제 기기 수신 검증을 대신하지 않는다.

## 실제 기기 QA

- [ ] iOS/Android에서 알림을 현재보다 몇 분 뒤로 설정하고 앱을 닫은 채 수신한다.
- [ ] 사진 저장 후 오늘 저녁 알림이 취소되고, 다음 날 예약은 유지되는지 확인한다.
- [ ] 오프라인 사진 저장 및 마지막 사진 삭제 후 예약 변화를 확인한다.
- [ ] 언어·개인 시간대 변경, 자정 통과, 앱 복귀 후 실제 예약을 확인한다.
- [ ] 최초 권한 거부, 설정 앱에서 권한 철회/허용, 알림 전체 끄기를 확인한다.
- [ ] 로그아웃·계정 삭제 중 예약 취소와 다른 계정에서 이전 알림을 누르는 동작을 확인한다.
- [ ] 종료·백그라운드·실행 상태에서 알림을 눌러 오늘 화면으로 이동한다.
- [ ] 비밀번호 복구 중 알림이 화면을 덮지 않고, 기존 친구방 알림도 계속 동작하는지 확인한다.

친구방 푸시의 실기기 검증에는 별도로 EAS 프로젝트 ID, 플랫폼별 푸시 자격 증명, development/release build와 두 테스트 계정이 필요하다. 이 작업에서는 푸시 자격 증명 설정이나 실제 푸시 발송을 수행하지 않는다.

공식 API와 플랫폼 참고: [Expo SDK 57 Notifications](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/).
