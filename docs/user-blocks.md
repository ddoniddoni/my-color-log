# 사용자 차단

요구사항: PRD `FR-ROOM-012`. 사용자가 선택한 범위는 **모든 공통 친구방의 양방향 사진·반응·사진 알림 차단**이다.

## 앱에서 사용하는 방법

- 다른 멤버의 오늘·과거 사진 상세 → 사용자 차단 → 확인.
- 친구방 관리 → 멤버 관리 → 차단 또는 차단 해제. 일반 멤버도 방장을 차단할 수 있다.
- 내 정보 → 차단한 사용자 → 대상의 차단 해제 → 확인. 방을 떠난 뒤에도 목록을 관리할 수 있다.
- 확인 화면은 현재 native Modal 안에서 전환한다. 한국어·영어, 라이트·다크 테마, 스크롤 및 44pt 이상 버튼을 제공한다.
- 서버 확인 전 성공 처리하지 않는다. 저장 중 중복 터치·닫기를 막고, 실패하면 안전한 안내와 재시도를 제공한다. 요청 제한은 20초이며 자동 재시도·오프라인 저장 대기열에는 넣지 않는다.

차단은 신고 접수와 독립적이다. 차단하거나 해제했다고 상대에게 푸시를 보내지 않는다. 서로 차단했다면 양쪽 모두 해제해야 서로의 콘텐츠를 다시 볼 수 있다. 관리용 멤버 목록, 방장 권한·멤버십·정원, 개인 기록·사진·공유 연결은 유지된다.

## 데이터와 권한

- `cl_user_blocks`: 차단한 사용자 ID + 대상 ID가 기본 키이며 생성 시각을 저장한다. 자기 자신은 차단할 수 없다. 대상 역방향 인덱스와 프로필 삭제 연쇄를 둔다.
- RLS로 내 outgoing 차단 행만 읽는다. 앱의 직접 INSERT/UPDATE/DELETE를 거절한다.
- `cl_set_user_block`: 공개 invoker → 비공개 구현. 유효한 영구 계정 Auth 세션을 검사하고 actor를 서버에서 결정한다. 새 차단에는 공통 활성 방이 필요하며 해제에는 필요하지 않다. 반복 요청은 같은 상태로 수렴한다.
- `cl_get_my_blocked_users`: 내 차단 목록의 ID·닉네임·시각만 반환한다. 다른 사람이 나를 차단한 목록은 제공하지 않는다.
- 두 사용자 임의 조합을 조회하는 내부 helper는 일반 계정에 실행 권한을 주지 않는다. RLS용 helper는 호출자 본인과의 관계만 검사한다.
- 공유 entry/photo/share 및 Storage SELECT, 방의 오늘·과거 보드와 참여 인원, 구형 단일 방 RPC, 사진 반응 조회·수정에 같은 차단 기준을 적용한다. 제3자의 사진에 달린 차단 대상의 반응도 집계에서 제외한다.
- 새 사진 알림의 대기열 생성·발송 전 payload 확인에서 차단을 검사한다. 차단 시 아직 보내지 않은 작업을 취소하며 해제해도 재발송하지 않는다. 차단과 enqueue가 동시에 실행되면 동일한 사용자 쌍 잠금으로 순서를 보장한다.
- 숨겨진 사진 신고는 거절하지만 공통 방의 멤버 신고는 가능하다.

## 화면 캐시와 사진 요청

차단·해제 성공 시 해당 사용자의 모든 방 보드·과거 보드·방 기록 요약·반응·차단 목록 요청을 취소하고 캐시를 초기화한다. query AbortSignal을 전달해 늦게 끝난 이전 요청이 사진을 되살리지 못하게 한다. 개인 다이어리·사진 업로드 대기열·멤버십 캐시는 이 대상에 포함하지 않는다.

다른 기기의 열린 방 화면은 15초 간격 조회 또는 화면 복귀 조회 때 반영된다. 오프라인 기기나 이미 내려받은 콘텐츠를 원격으로 회수하는 기능은 아니다.

친구방 사진은 기존 1시간 signed URL 대신 인증된 Storage 경로를 사용한다. 현재 세션 헤더는 렌더링할 때만 붙이고 query data/키·영속 저장소에 넣지 않는다. 공유 사진의 Expo Image 캐시 정책은 `none`이다. 개인 다이어리의 기존 사진 경로는 유지한다.

실제 서버에서 `Cache-Control: no-cache` 요청과 업로드 `max-age=0`만으로는 이전 성공 응답의 CDN HIT가 없어지지 않았다. **사진 화면을 새로 열 때마다 `cacheNonce`를 생성**해 원본 서버의 현재 권한을 확인한다. 화면이 열린 동안 nonce를 유지하므로 15초 보드 재조회마다 모든 사진을 다시 다운로드하지 않는다. 세션 갱신 시 Authorization 헤더는 갱신된다.

근거: [Supabase 비공개 파일 접근](https://supabase.com/docs/guides/storage/serving/downloads), [CDN 캐시 우회](https://supabase.com/docs/guides/storage/cdn/smart-cdn).

### 회수 한계

이미 다운로드·캡처한 사진, 이전에 발급한 signed URL, 이미 CDN에 저장된 성공 응답 주소는 즉시 회수할 수 없다. 임시 주소의 유효기간과 CDN 캐시 만료는 별개이며, 단순 Auth 세션 해지로 기존 signed URL이 폐기되지도 않는다. 이번 변경은 **최신 앱에서 새로운 사진 요청이 현재 권한을 검사하도록** 보완한다. 파일 삭제·사진 경로 이동·Storage 키 변경으로 다른 멤버의 정상 접근이나 개인 데이터를 훼손하지 않는다.

이미 Expo/APNs/FCM으로 넘긴 알림도 회수할 수 없다. 대기열 취소 이후 실제 발송 여부는 발송 직전 검사와 외부 전송 사이의 경합에 영향을 받을 수 있다.
