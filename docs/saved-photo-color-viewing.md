# 오늘 사진 다시 보기의 색 강조

요구사항: PRD FR-PHOTO-002.

오늘 탭에서 저장한 사진을 누르거나 길게 눌러 사진 관리 화면을 연다. 사진 아래 `오늘의 색만 보기` 스위치를 켜면 해당 날짜의 미션 색을 남기고, 끄면 저장된 사진으로 돌아간다. 선택은 이 기기의 계정·날짜·사진·미션 색별로 기억하며 닫은 뒤 오늘의 9칸과 다시 연 상세 화면에도 반영한다. 앱 재실행 후에도 해당 날짜의 선택을 복원한다.

## 처리 범위

- `SavedPhotoColorViewer`는 로컬 URI 또는 기존 개인 사진 signed URL을 공통 `ColorIsolationPreview`에 전달한다. 화면 너비 측정 후 사진 해상도에서 처리하고 정사각형 영역에 축소 표시한다.
- 보기 전용 `isolate` 모드는 기존 분류기를 사용하되 채도 증가와 배경 어둡게 처리를 끈다. 저장 사진의 명암·채도를 반복해서 강화하지 않는다.
- 파일 생성·교체·업로드·DB 수정·업로드 큐 갱신은 실행하지 않는다. AsyncStorage에는 계정당 최근 선택 날짜 한 개와 최대 9개의 사진 ID·색만 저장한다. URI·픽셀·인증 정보를 저장하지 않으며 다른 기기나 친구방에는 전파하지 않는다. 촬영 직후 저장하는 기존 `emphasize` 모드는 그대로 유지한다.
- 설정 쓰기는 계정별 직렬 처리하며 성공 후 상세와 9칸에 함께 반영한다. 저장 실패는 이전 선택을 유지하고 안내한다. 읽기 실패에는 재시도를 제공한다. 네트워크 없이도 설정을 읽고 쓸 수 있다.
- 9칸은 선택한 사진만 필터 처리한다. 분류는 사진 해상도에서 수행한 뒤 CPU surface에서 긴 변 384px 이하로 축소하여 큰 처리 결과를 해제한다. 상세 창에 열린 사진의 그리드 필터는 해제하고 닫으면 다시 표시한다. 그리드 처리 실패는 저장 사진과 재시도 안내로 표시하며 상세에서 다시 확인할 수 있다.
- 로컬 큐의 `colorIsolationApplied`가 확인되면 체크된 비활성 스위치와 이미 적용된 사진이라는 안내를 표시하고 필터를 다시 실행하지 않는다. 서버 사진 행에는 과거 효과 적용 메타데이터가 없으므로 다른 기기·로컬 기록이 없는 사진의 적용 이력을 추측하지 않는다. 이런 사진은 저장된 파일을 바탕으로 보기 전용 모드만 실행한다.
- 이미 흑백 효과로 저장한 사진의 원래 색을 복원하는 기능은 아니다. 스위치를 껐을 때의 기준은 원본 촬영 파일이 아니라 현재 저장된 사진이다.
- 사진 주소·유효한 색·레이아웃이 없거나 네이티브 렌더러가 없으면 토글을 비활성화한다. 사진 이동·삭제·확인 대화상자 중에도 비활성화한다. 렌더 실패 시 저장된 사진으로 복귀하고 사용자가 다시 켜서 재시도할 수 있다.

## 검증

- 로컬/서버 URI 토글, 화면 크기 전달, 닫기 후 선택 유지와 그리드 반영, 다른 사진·미션 색 분리, 오류 복귀·재시도, 중복 효과 방지, 주소·색·레이아웃 누락과 삭제 중 비활성화를 컴포넌트 테스트로 확인한다.
- 새 QueryClient를 사용한 재실행 복원, 계정·날짜 구분, 오프라인·연속 토글, 저장 실패와 읽기 재시도, 최대 9개 메타데이터 제한을 검증한다. 작은 그리드 이미지 생성 후 큰 raster 해제를 모의 렌더 테스트로 확인한다.
- 로컬/동기화 사진의 효과 적용 메타데이터 전달과 서버 전용 사진의 알 수 없는 상태를 모델 테스트로 확인한다.
- 실제 SkSL 렌더 테스트로 보기 전용 모드에서 목표색 채도와 이미 회색인 픽셀의 밝기가 유지되고 다른 색은 흑백이 되는지 확인한다.
- 새 서버 설정·마이그레이션·의존성은 없다. 빌드 및 실기기 확인은 마지막 통합 QA에 남긴다. iPhone/Android에서 로컬·업로드 완료 사진, 비행기 모드, 재시도, 큰 글자·두 테마, 사진 관리 이동·삭제를 확인한다.

## 검게 표시되는 미리보기 보완

저장 사진에서 토글을 켜면 검게 보인다는 기기 제보를 받았다. 코드 확인 결과, JS 스레드의 offscreen surface에서 만든 GPU snapshot을 그대로 Canvas 렌더 스레드에 전달하고 있었다. 설치된 Skia의 `src/renderer/Offscreen.tsx`는 snapshot을 `makeNonTextureImage()`로 변환하며, [Canvas 문서](https://wcandillon.github.io/react-native-skia/v2/docs/canvas/overview/)도 텍스처 접근에 같은 렌더 컨텍스트가 필요함을 설명한다.

공통 렌더러에서 surface가 살아 있는 동안 CPU-backed 이미지로 변환하고 GPU snapshot을 해제하도록 수정했다. 변환 실패는 명시적으로 실패 처리하여 기존 미리보기 오류 경로로 저장 사진에 복귀한다. 원본 파일과 색 분류 기준은 바꾸지 않는다. 저장 경로 역시 변환 실패 시 파일·큐를 변경하지 않는다.

변환 실행과 surface 해제 순서, null/예외 실패 시 원본 보존 및 GPU 자원 정리를 회귀 테스트로 확인한다. 테스트는 GPU 컨텍스트를 모의하며 실제 iPhone의 검은 화면 재현/해소를 증명하지 않는다. 수정된 JS를 로드한 기기에서 동일 사진 토글을 다시 확인해야 한다. CPU readback에 따른 최대 메모리·처리 시간은 최종 기기 QA 대상이다.
