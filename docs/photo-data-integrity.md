# 사진 복구와 친구방 접근권한 통합

관련 요구사항: FR-PHOTO-003/004/006/007, FR-AUTH-005, FR-MISSION-002/004, FR-ROOM-007/009.

`2206800`의 사진 복구 수정과 `96079d4`의 방 시간대 수정을 최신 색상 공개·비밀번호 재설정·기록 알림 구현에 통합했다. 기존 커밋이나 migration 이력을 다시 작성하지 않는다.

## 동작

- 서버에서 삭제·정렬·캡션 수정이 완료된 사진은 서버 메타데이터를 따른다. 동기화된 로컬 파일은 이미지 캐시로만 사용하므로 삭제된 사진을 다시 표시하지 않는다.
- 중단된 업로드가 서버에 이미 존재하면 기존 사진으로 수렴하고, 다른 기기에서 편집한 캡션이나 순서를 덮어쓰지 않는다. 업로드 직전 서버의 빈 자리를 확인하며 충돌 시 재조회한다. 9장이 찬 경우 로컬 파일을 보존한다.
- 업로드·삭제·정렬·삭제 후 정리는 계정의 QueryClient에서 같은 mutation scope로 순서대로 실행한다. 삭제된 사진의 `cancelled` 기록은 동기화 작업이 최종 정리를 마칠 때까지 유지한다. 서버에서 삭제를 거절하면 기존 큐 상태로 복구하고, 대기 중인 정리 작업도 실행 직전 취소 상태를 재확인한다.
- 미확정 촬영 초안은 날짜·색 정보·캡션과 함께 보관한다. 오늘 화면에서 이어서 확인할 수 있고 자동 업로드하지 않는다. 다른 화면을 보고 있을 때 복구 모달을 띄우지 않아 비밀번호 복구를 가리지 않는다.
- 현재 계정의 프로필·개인 기록 메타데이터·서버 미션·공개 팔레트만 최대 96건까지 기기에 캐시한다. 친구 사진과 친구방 데이터, signed URL, 인증 토큰은 이 캐시에 저장하지 않는다. 로그아웃·계정 변경·삭제 시 이전 계정 캐시를 정리한다.
- 캐시가 있는 날짜는 오프라인 재실행 후에도 기록을 계속할 수 있다. 캐시가 없는 날짜에는 연결 안내를 제공하며 임의의 미션을 만들지 않는다. 계정·날짜별 색상 공개 이력과 ‘이 색으로 기록하기’ 동작은 유지한다.
- 오프라인 세션은 기존 SecureStore에서 읽어 로컬 화면 복구에만 사용한다. 원격 권한은 Supabase 인증과 RLS가 계속 검증한다. 늦은 세션 조회가 로그아웃이나 새 로그인을 덮어쓰지 않는다.
- 알림 재조정과 업로드 시작은 계정 캐시 복원이 끝난 후 진행한다. 미확정 초안은 기록 완료로 집계하지 않는 기존 알림 정책을 유지한다.

## DB 변경

기존 브랜치의 `20261016173318_align_room_visibility_timezones.sql`을 그대로 가져왔다. RLS가 실제로 호출하는 private helper를 방의 IANA 시간대에 맞추고, 사용하지 않는 public 중복 helper 3개를 제거한다. DROP은 RESTRICT로 실행하므로 예상하지 못한 의존성이 있으면 적용이 중단된다. 사진·기록·기존 date key를 변경하거나 삭제하지 않는다.

운영 DB에는 아직 적용하지 않았다. 배포 시 기존 migration 적용 이력을 확인하고, 중복 적용 없이 이 migration까지 적용해야 한다.

## 검증과 한계

```sh
npm test -- --runInBand
npm run typecheck
npm run lint
npx react-doctor@latest --verbose --scope changed
CI=1 EXPO_NO_DOTENV=1 npx expo export --platform ios --platform android --output-dir /tmp/mycolorlog-photo-integrity-export
```

회귀 테스트는 오프라인 캐시 재시작과 공개 결과 유지, 초안 보관·동시 확정, 서버 사진 정렬·삭제·중복 업로드, 삭제 취소 기록과 작업 순서, 로그아웃·계정 전환의 늦은 응답, 복구 화면의 모달 가림을 검증한다. 기존 비밀번호 재설정·색상 공개·알림 테스트도 함께 실행한다.

최종 검증: 61개 suite·269개 테스트, typecheck, lint, iOS·Android 번들 생성, `git diff --check` 통과. React Doctor는 신규 파일을 포함한 변경 코드 46개를 검사했고 새 진단이 없었다. 네이티브 빌드와 실제 설치 실행은 포함하지 않는다.

로컬 PostgreSQL 17에 migration 32개를 처음부터 적용하고 SQL 계약 테스트 5개를 실행했다. 방 가시성 테스트는 744개 조회 결과를 비교한다. 수정 전 migration에서는 가입일·미래 날짜 접근 실패가 재현되고, 수정 후에는 통과한다. 로컬 DB security advisor에서 warning/error가 검출되지 않았다.

Docker가 없는 환경이므로 DB 검증은 임시 embedded PostgreSQL과 Auth/Storage 최소 스키마를 사용했다. 실제 조회는 `authenticated` 역할과 사용자별 JWT claim 설정으로 RLS를 평가했다. 실제 Supabase Auth가 발급한 세션과 Storage HTTP API 검증, iOS/Android 실기기의 촬영·강제 종료·재연결은 아직 별도 QA가 필요하다. 로컬 재현은 [DB 계약 테스트 안내](../supabase/tests/README.md)를 따른다.

새 앱 의존성이나 환경 변수는 추가하지 않았다. 이 문서는 DB 배포·스토어 제출·실기기 QA 완료를 뜻하지 않는다.
